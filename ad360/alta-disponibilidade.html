Continuidade & resiliência

Alta disponibilidade (High Availability)

Garante que o AD360 (ou um componente) continue disponível mesmo se o servidor principal cair — essencial quando o console de identidade não pode ficar fora do ar.

Como funciona

A HA do AD360 usa um modelo de failover automático com dois servidores:

Quando o servidor primário fica indisponível, o standby assume — sem o usuário precisar trocar de URL.

Os dois servidores compartilham o mesmo banco de dados. Em qualquer momento, apenas um está ativo atendendo requisições; o outro fica passivo até uma indisponibilidade prolongada do primário.

ESCOPO

Além do AD360 em si, a configuração de HA está disponível para ADManager Plus, ADSelfService Plus e M365 Manager Plus — os três componentes com suporte oficial a essa configuração.

Pré-requisitos

  • Conexões TCP/IP entre o AD360 e o banco de dados não podem estar bloqueadas por firewall em nenhum dos dois servidores.
  • Se o banco for MS SQL Server, versão superior à 2005.
  • Ambas as instâncias do produto devem: estar instaladas e rodando como serviço; ter a mesma arquitetura (32 ou 64 bits), versão e número de build; estar conectadas ao mesmo domínio e à mesma rede — inclusive o IP virtual precisa estar na mesma faixa de IP dos dois servidores.

Configuração passo a passo

Acesse a tela de HA

Admin → Administration → High Availability — selecione o componente (ou o próprio AD360) que vai receber a configuração.

Servidor primário

A URL do servidor que você está acessando agora já vem preenchida automaticamente.

Servidor secundário (standby)

Informe o nome/IP do servidor que vai assumir nas indisponibilidades, e as credenciais de super admin daquela instância.

IP virtual

Um IP estático não utilizado na rede (teste com ping — se der "tempo esgotado", está livre) que vai rotear para quem estiver ativo. Opcionalmente, defina também um hostname virtual (alias do IP, configurado no seu servidor DNS).

Salvar

A partir daqui, todo acesso (inclusive a integração no AD360) deve usar o IP/hostname virtual — nunca o IP do servidor primário diretamente.

Como desativar

REGRA IMPORTANTE

A alta disponibilidade só pode ser desativada a partir do servidor standby. Para isso: pare o serviço no servidor primário e inicie-o no standby antes de desabilitar a configuração.

Se o MS SQL tiver "Force Encryption" habilitado

Quando o SQL Server usado pelo AD360 exige criptografia forçada na conexão, é preciso replicar o certificado entre os servidores:

Copie o certificado

Copie o arquivo .cer gerado no servidor primário para o servidor secundário.

Importe no Java KeyStore

No servidor secundário, abra o Prompt de Comando em <diretório de instalação>\jre\bin e rode:

keytool -import -v -trustcacerts -alias myserver -file caminho\certificado.cer -keystore "..\lib\security\cacerts" -keypass changeit -storepass changeit -noprompt
