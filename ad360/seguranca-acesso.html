Logon Settings

Segurança de acesso ao console

Tudo que fica em Admin → Administration → Logon Settings — a camada de proteção de quem consegue logar no AD360, e como.

Configurações gerais

CAPTCHA

Habilita um desafio CAPTCHA na tela de login, dificultando ataques automatizados de força bruta.

Bloqueio por tentativas inválidas

Bloqueia o usuário depois de um número configurável de tentativas de senha incorretas.

Ocultar "Esqueci minha senha"

Remove o link de recuperação de senha da tela de login — útil quando esse fluxo é gerenciado fora do AD360.

Single Sign-On (SSO)

Permite que usuários já autenticados no domínio Windows entrem no AD360 automaticamente, sem digitar senha de novo. O AD360 suporta dois métodos:

NTLM

SSO transparente dentro da rede corporativa, aproveitando a sessão Windows já autenticada no domínio — sem depender de um provedor de identidade externo.

SAML

Integração com um provedor de identidade (IdP) externo — ADFS, Okta, Azure AD e outros compatíveis com SAML 2.0. Cada IdP tem seu próprio passo a passo de configuração (troca de metadata/certificado entre as duas pontas).

ONDE PEGAR OS DADOS PARA O IDP

Ao configurar SAML, o AD360 gera valores como Entity ID, Issuer URL, SP Logout URL e um certificado X.509 — todos disponíveis em Logon Settings → Single Sign-On → SAML Authentication, para colar na configuração do lado do provedor de identidade.

Autenticação por smartcard

Permite autenticar usuários via cartão inteligente (smartcard), pulando o primeiro fator tradicional de usuário/senha — comum em ambientes governamentais ou de alta exigência de segurança física.

Autenticação em dois fatores (2FA)

Depois de habilitada em Logon Settings → Two-factor Authentication, o usuário precisa de um segundo fator além da senha de domínio. Métodos suportados:

Verificação por e-mail

Código de verificação enviado ao e-mail cadastrado do usuário.

Verificação por SMS

Código enviado por mensagem de texto (depende do SMS configurado em Server Settings).

Google Authenticator / Microsoft Authenticator

Apps de autenticação baseados em TOTP.

RSA SecurID

Integração via SDK (arquivo sdconf.rec) ou REST API com o RSA Authentication Manager.

Duo Security / RADIUS

Integração com provedores corporativos de MFA já usados pelo cliente.

Custom TOTP / códigos de backup

Suporte a autenticadores TOTP genéricos e códigos reserva para quando o segundo fator não está disponível.

MÚLTIPLOS MÉTODOS

Se mais de um método estiver habilitado ao mesmo tempo, o usuário escolhe qual usar no momento do login.

Restrição por IP

Permite liberar ou bloquear o acesso ao AD360 e aos componentes integrados com base no endereço IP de quem está tentando acessar — útil para travar o console a redes internas/VPN específicas.

RELEVANTE PARA HA

Se você habilitar Alta Disponibilidade, lembre de adicionar o IP virtual na lista de IPs permitidos aqui — senão o failover pode ficar bloqueado pela própria restrição. Ver Alta disponibilidade.
