Do kickoff ao primeiro login: implantando o AD360 num cliente

Este é o roteiro de ponta a ponta pra quem está entrando na casa do cliente pela primeira vez: o que levantar antes, em que ordem instalar e integrar, o que travar de segurança antes de entregar o acesso, e como validar que ficou tudo redondo.

RELAÇÃO COM OUTRAS PÁGINAS

Esta página foca na sequência do projeto. Para o passo a passo técnico de cada tela (modos de instalação, SSL, backup), veja Instalação & operação. Para o significado de cada componente, veja Os 7 componentes.

Antes de instalar: o que levantar com o cliente

Boa parte dos retrabalhos em implantação de AD360 vem de informação que não foi levantada no kickoff. Confirme isso antes de tocar em qualquer instalador:

Escopo de componentes

Quais dos 7 componentes o cliente efetivamente licenciou/vai usar? Isso define o dimensionamento de hardware e quantos servidores serão necessários (lembrando: no máximo 2 componentes por máquina).

Conta de serviço

Uma conta de domínio já provisionada, com os privilégios mínimos por componente (ver Permissões) — idealmente Domain Admin para a implantação inicial, revisado depois.

Topologia de rede

Onde ficarão o AD360 e cada componente (mesma VLAN dos DCs? DMZ? acesso via VPN?) — define quais portas da página de Requisitos & portas precisam ser liberadas antes do dia da instalação.

Certificado SSL

O cliente já tem um certificado válido para o hostname que será usado, ou vamos gerar um autoassinado/CSR na implantação?

Servidor de e-mail

Host, porta, tipo de autenticação e um destinatário de teste para validar alertas e notificações assim que o console subir.

Banco de dados

PostgreSQL embutido é suficiente, ou o cliente exige MS SQL Server (política interna, equipe de DBA própria etc.)? Isso muda o prazo — migração de banco é uma etapa própria.

Sequência recomendada de implantação

1. Instalar o AD360

Modo Standard se o cliente vai usar a maioria dos 7 componentes; Custom se só uma parte. Instale como aplicação primeiro, depois promova para serviço do Windows antes de sair do site.

2. Instalar os componentes selecionados

Baixe e instale cada componente individualmente, e inicie cada um pelo atalho antes de tentar integrar — o AD360 só enxerga um componente que já está rodando.

3. Integrar cada componente

Em Admin → Administration → AD360 Integration, um tab por componente: host/IP, porta, protocolo, e as credenciais do super administrador do componente (não é a conta de domínio — é o admin local daquele produto).

4. Configurar o domínio uma única vez

Adicione o domínio em qualquer um dos componentes integrados — ele se propaga para os demais automaticamente. Não repita esse passo em cada componente.

5. Configurar tenants de nuvem (se aplicável)

Microsoft 365 e Google Workspace são configurados por componente (ADManager Plus, M365 Manager Plus, RecoveryManager Plus cada um tem sua própria tela de tenant) — não sincronizam automaticamente como o domínio on-premises.

ALTA DISPONIBILIDADE

Se algum componente já estiver configurado em HA, use o IP/hostname virtual do cluster na integração — não o IP do servidor primário. Apontar para o servidor primário direto quebra o failover depois.

Hardening do console antes de entregar o acesso

Antes de repassar as credenciais para o time do cliente, esses ajustes evitam retorno em campo por causa de segurança básica:

Trocar a senha padrão

Admin → General Settings → Personalize → Change Password — o login admin/admin nunca deve sobreviver ao dia da implantação.

Configurar técnicos, não usar só o super admin

Crie os técnicos do cliente com o papel correto (Admin ou Operator) em Administration → Manage Technicians — ver detalhes na página Técnicos & delegação.

Login Settings — proteções básicas

Em Administration → Logon Settings → General: habilitar CAPTCHA e bloqueio após tentativas inválidas. Em ambientes com política mais rígida, habilitar 2FA para quem tem papel Admin. Detalhe completo em Segurança de acesso.

SSO, se fizer sentido pro cliente

Se os usuários já autenticam no domínio Windows, o Single Sign-On (NTLM ou SAML) evita mais uma senha para gerenciar — vale a conversa no kickoff.

Restringir por IP, se acesso é só interno

Logon Settings → Allow/restrict IPs — útil quando o AD360 não deveria ser alcançável fora da rede corporativa/VPN.

SSL aplicado, não pendente

Gere o CSR ou aplique o certificado do cliente antes de sair do site — ver o passo a passo em Instalação → Habilitando SSL.

Checklist de validação pós-implantação

Antes de considerar o projeto encerrado, confirme cada item:

SMOKE TEST

✓ Login funciona com a nova senha de admin e com pelo menos um técnico do cliente
✓ Todos os componentes contratados aparecem no painel lateral de aplicações
✓ O domínio aparece corretamente em todos os componentes integrados
✓ Um e-mail de teste (alerta ou notificação) chega no destinatário configurado
✓ O certificado SSL está aplicado e o navegador não mostra aviso de "não seguro"
✓ O backup automático está agendado (ver Instalação → Backup automático)
✓ Sync manual (Sync Now) roda sem erro

Handoff para operação e suporte

O que deixar documentado com o cliente ao final da implantação:

  • Credenciais de acesso entregues por canal seguro (não por e-mail em texto puro) — senha de admin trocada, técnicos já cadastrados.
  • URL de acesso e certificado — se autoassinado, avisar o time do cliente sobre o aviso de navegador esperado.
  • Janela e retenção do backup automático configurado.
  • Política de atualização automática definida (ligada ou não, e com qual frequência de verificação).
  • Contato de suporte oficial ManageEngine para abertura de chamados técnicos.
