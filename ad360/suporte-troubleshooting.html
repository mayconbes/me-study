Suporte e troubleshooting

Os problemas mais recorrentes de quem já opera um AD360 em produção — e onde buscar ajuda quando o problema não é nenhum destes.

Erros comuns de integração entre AD360 e componentes

SintomaCausa provávelSolução
Falha de comunicação / sincronização entre AD360 e um componenteComponente parado, porta bloqueada por firewall, ou protocolo (HTTP/HTTPS) incorreto selecionado na integraçãoConfirmar que o componente está rodando, que a porta está liberada no firewall, e que o protocolo escolhido bate com o que o componente está usando
Não consigo integrar um segundo servidor do mesmo componenteJá existe uma instância daquele componente integrada — o AD360 só permite uma por vezEm Admin → Administration → AD360 Integration, remover a instância atual (botão Remove) antes de integrar a nova
Peço as credenciais de super admin ao integrar um componente remotoComportamento esperado — não é erroInformar as credenciais do super administrador daquele componente, não da conta de domínio
Dashboard de um componente não aparece / fica em brancoDomínio selecionado no momento não é o mesmo configurado naquele componente, ou o login atual não tem permissão nesse domínioConferir o seletor de domínio no topo da tela e trocar para o domínio correto antes de acessar o componente

SSL, HTTPS e SMS

Erro ao habilitar HTTPS

Ao ativar HTTPS, o AD360 atribui automaticamente uma porta HTTP com base na porta HTTPS escolhida. Se essa porta gerada já estiver em uso por outra aplicação, a ativação falha. Solução: volte para HTTP, troque a porta para uma livre, e tente HTTPS de novo.

SSLHandshakeException em SMS/e-mail

Ocorre quando o servidor SMTP ou o gateway de SMS usa um certificado autoassinado — o Java (que roda o AD360) não confia nele por padrão. Solução: exportar o certificado do servidor (com OpenSSL, por exemplo) e importá-lo manualmente no keystore Java usado pelo AD360.

Backup e restauração manual do banco

Além do backup automático (ver Instalação → Backup automático), existe um caminho manual via linha de comando — útil em migrações de servidor:

Pare o AD360

Interrompa o serviço/aplicação antes de manipular o banco.

Rode o script de backup

No Prompt de Comando: <AD360_Home>\bin\backupDB.bat — gera um .zip em <AD360_Home>\Backup\.

Para restaurar em outro servidor

Instale a mesma versão do AD360 no novo servidor, copie o .zip do backup e o arquivo specs.xml (da pasta Patch), e rode restoreDB.bat <nome_do_zip> na pasta bin do novo servidor.

NÃO DESMONTE O AMBIENTE ANTIGO AINDA

Mantenha a instalação antiga rodando até confirmar que a nova está funcionando corretamente — é a rede de segurança da migração.

Como enviar logs para o suporte

Quando o suporte pede os logs do produto para investigar um chamado:

Localize o arquivo

Na pasta de instalação, abra logs\archive — o arquivo relevante segue o padrão de nome ssmmHHddMMyyyy.zip.

Envie

Anexe o .zip por e-mail para ad360-support@manageengine.com. Se o arquivo for grande demais para e-mail, o suporte disponibiliza um portal de upload próprio — peça o link atualizado ao abrir o chamado.
