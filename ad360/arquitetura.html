Arquitetura

Como o AD360 integra os componentes

O AD360 não é um instalador único disfarçado — é uma camada de orquestração. Entender esse modelo é a base para configurar, atualizar e dar suporte a qualquer ambiente AD360.

Modelo hub-and-spoke

Cada componente (ADManager Plus, ADAudit Plus, etc.) é um produto independente, com seu próprio processo, sua própria porta e seu próprio banco de dados. O AD360 funciona como o hub: ele se conecta a cada um pela rede (host + porta), e a partir daí passa a exibir o dashboard deles dentro do seu próprio console.

MODELO

Isso significa que os componentes podem estar todos na mesma máquina do AD360, ou distribuídos em servidores diferentes — o que importa é que o AD360 consiga alcançá-los via rede.

Fluxo de integração passo a passo

É basicamente assim que qualquer implantação de AD360 nasce:

O domínio é configurado uma única vez — em qualquer componente — e se propaga para os demais automaticamente.

Instalar o AD360

Como aplicação ou como serviço do Windows. Se a instalação for Standard, os componentes já vêm junto e essa etapa é automática.

Instalar os componentes desejados

Baixar o instalador de cada componente (pelo próprio dashboard do AD360 ou pelo site) e instalar individualmente.

Registrar cada componente no AD360

Em Admin → Administration → AD360 Integration, informar nome/IP do servidor, porta e protocolo de cada componente, e clicar em Integrate Now.

Configurar o domínio em qualquer componente

O domínio só precisa ser adicionado uma vez, em qualquer componente — a informação se propaga para os demais.

Acessar tudo pelo painel lateral

A partir daqui, o AD360 mostra os dashboards de cada componente integrado no menu de aplicações à esquerda.

A — escolha o componente que está integrando (a aba muda o formulário abaixo).
B — nome/IP e porta do servidor onde aquele componente está instalado, não do AD360.
C — HTTP ou HTTPS, precisa bater com o que o componente está usando de fato.
D — depois de clicar, o status abaixo confirma a conexão e mostra a última sincronização.

Esquema simplificado — não é o design real do console, é uma representação genérica de onde cada campo do passo 3 fica.

O que é sincronizado automaticamente

A sincronização acontece porque os componentes "conversam" entre si — mudanças de hostname/porta de um precisam ser refletidas nos outros para não quebrar o single sign-on. O AD360 automatiza essa propagação para:

Configurações de domínio

Domínio adicionado ou credenciais alteradas em um componente valem para todos os integrados.

Servidor de e-mail

SMTP configurado uma vez, usado por todos para alertas e notificações.

Proxy

Configuração de proxy corporativo compartilhada entre os componentes.

DICA

Se algo não sincronizar automaticamente, vá em Admin → Administration → AD360 Integration → Sync Now para forçar a sincronização manual.

Alta disponibilidade

Alta disponibilidade (HA) garante que o AD360 continue operando mesmo se o servidor principal falhar — essencial em ambientes de produção onde o console de identidade não pode ficar fora do ar. Veja o passo a passo completo em Alta disponibilidade.

Proxy reverso

O AD360 também pode atuar como proxy reverso para os produtos integrados, de duas formas:

  • Baseado em contexto: cada componente responde em um caminho diferente (ex: /admanager) sob o mesmo domínio e porta.
  • Baseado em porta: cada componente responde em uma porta diferente, mas ainda intermediado pelo AD360.

Isso simplifica o acesso externo: em vez de expor sete URLs e portas diferentes, expõe-se apenas o AD360. Detalhe completo com diagrama em Proxy reverso.
