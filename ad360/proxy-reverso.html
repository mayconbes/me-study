Acesso externo

AD360 como proxy reverso

Em vez de expor sete URLs e portas diferentes para usuários externos, o AD360 pode ficar na frente de tudo — os componentes ficam escondidos atrás dele.

Por que usar um proxy reverso aqui

Um proxy reverso fica entre o usuário externo e os servidores internos: o cliente nunca fala diretamente com o servidor da aplicação, apenas com o proxy — que repassa a requisição internamente e devolve a resposta. Isso significa:

Uma única porta de entrada

O firewall só precisa liberar acesso externo ao AD360, não a cada componente individualmente.

Servidores internos escondidos

O usuário externo nunca sabe o hostname/IP real de onde o ADManager Plus, ADAudit Plus etc. estão rodando.

Menos superfície de ataque

Máquinas com os componentes instalados podem ficar totalmente na rede interna, sem exposição direta.

O AD360 suporta dois modelos — contexto e porta — que podem ser habilitados juntos ou separadamente, conforme o desenho de rede do cliente.

Proxy reverso baseado em contexto

Cada componente responde em um caminho (path) diferente, sob o mesmo hostname e porta do AD360.

Acesse a tela

Admin → Administration → Reverse Proxy → aba Context Based e marque Enable Context Based Reverse Proxy.

Escolha protocolo e porta

Confirme que a porta escolhida não está em uso por outra aplicação no servidor.

Defina o caminho de cada componente

Para o AD360 e cada componente integrado, informe um context path único (ex: /admanager, /adaudit).

Anote as Access URLs geradas

São essas URLs que os usuários externos vão usar para acessar cada produto.

Salve

Save Settings aplica a configuração.

Proxy reverso baseado em porta

Cada componente responde em uma porta diferente, mas o hostname continua sendo o mesmo do AD360 para todos.

DIFERENÇA-CHAVE

Aqui, a porta é obrigatória ser única por servidor; o protocolo é opcional. No modelo por contexto, é o caminho da URL que precisa ser único — a porta é compartilhada.

Cenário típico: AD360 na DMZ

O usuário externo só enxerga o AD360; os componentes ficam na rede interna, alcançáveis apenas pelo proxy.

O firewall permite que apenas o AD360 alcance os componentes internos — máquinas externas nunca se conectam diretamente aos servidores das ferramentas.
