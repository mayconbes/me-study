Guia prático para consultores

Implantando o ADManager Plus num cliente

Diferente do AD360, aqui não existe "integração de componentes" — é uma instalação única. O trabalho pesado do projeto está em desenhar corretamente delegação, templates e workflow antes de entregar o acesso ao help desk.

Antes de instalar: o que levantar

Edição a licenciar

Free (até 100 objetos, domínio único), Standard ou Professional — ver Licenciamento. Se o cliente precisa de workflow e automação, é Professional.

Add-ons necessários

O cliente precisa de backup/recovery de AD? De avaliação de risco e certificação de acesso (GRC)? Esses são add-ons separados — orçar com antecedência.

Domínios e florestas

Quantos domínios o cliente tem, e existe mais de uma floresta? Define o esforço de descoberta e configuração inicial.

Conta de serviço

Privilégio necessário conforme as operações que o cliente vai usar — ver Permissões. Nem sempre precisa ser Domain Admin.

Mapa de delegação

Quem no cliente vai ser help desk, o que cada um pode fazer, e em quais OUs — esse desenho deve existir antes de configurar o produto, não ser inventado na hora.

Cloud: M365 / Google Workspace

O cliente vai gerenciar identidades híbridas? Vai precisar do módulo Azure AD instalado na mesma máquina (para Microsoft 365) e/ou credenciais de admin do Google Workspace.

Instalação e primeiro acesso

Baixe e instale

Execute o instalador (.exe) e siga o install shield. Se estiver em Windows Vista ou versões antigas, desabilite o Controle de Conta de Usuário (UAC) antes, senão só o administrador consegue instalar.

Escolha aplicação ou serviço

Como aplicação, roda com o privilégio do usuário logado. Como serviço do Windows, roda com a conta de sistema — recomendado para produção, já disponível como opção no próprio instalador.

Inicie e acesse

Abra http://<hostname>:8080 no navegador (porta padrão HTTP). Login inicial: admin/admin.

Troque a senha padrão

Assim como em qualquer produto ManageEngine, esse é o primeiro passo de segurança antes de qualquer outra coisa.

Configurando o domínio

Na primeira execução, o ADManager Plus já tenta descobrir automaticamente os domínios visíveis a partir do servidor. Para adicionar manualmente (domínio filho, outra floresta, ou domínio não descoberto):

Abra Domain Settings

No canto superior direito do console.

Adicione o domínio

Informe o nome do domínio e use Discover para localizar os controladores de domínio automaticamente, ou adicione-os manualmente. O primeiro DC da lista é tratado como primário.

Informe as credenciais

Uma conta com privilégio administrativo (ou permissões granulares suficientes) sobre o domínio.

Sequência recomendada de configuração

Depois do domínio configurado, a ordem que evita retrabalho:

Cada etapa depende da anterior — pular direto para automação sem papéis e templates definidos é a receita clássica de retrabalho.

1. Templates de criação/modificação de usuário

Padronize antes de delegar — ver Gestão de usuários. Um help desk sem template bom vai criar inconsistência desde o primeiro usuário.

2. Papéis de help desk

Crie os papéis (roles) antes dos técnicos — ver Delegação & help desk.

3. Técnicos e escopo

Cadastre os técnicos, atribua papéis e restrinja por OU/grupo/site conforme o mapa de delegação levantado no kickoff.

4. Workflow, se necessário

Se o cliente exige aprovação antes de executar (ex: exclusão de usuário), configure requester/approver/executor antes de liberar o acesso ao help desk.

5. Automações e relatórios agendados

Rotinas como limpeza de contas inativas ou relatórios semanais só depois que a base (templates, delegação) está estável.

Checklist de validação pós-implantação

SMOKE TEST

✓ Login funciona com a senha de admin trocada e com pelo menos um técnico de teste
✓ O(s) domínio(s) aparece(m) corretamente, com todos os DCs esperados
✓ Um usuário de teste criado com o template correto aplica todos os atributos esperados
✓ O técnico de teste só enxerga/consegue agir nas OUs delegadas a ele — não no domínio inteiro
✓ Se houver workflow, uma requisição de teste percorre todos os níveis configurados
✓ Um relatório agendado chega por e-mail no destinatário certo

Handoff para operação

  • Documentar o mapa de delegação implementado (quem, o quê, onde) — não deixar isso só na cabeça de quem implantou.
  • Credenciais de admin entregues por canal seguro, com a senha padrão já trocada.
  • Lista de templates criados e o que cada um padroniza.
  • Se houver automação ativa, documentar o que roda, quando, e o impacto de desativar.
  • Contato de suporte oficial ManageEngine para chamados técnicos.
