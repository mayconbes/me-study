Implantando o ADAudit Plus num cliente

Diferente de uma ferramenta de gestão, aqui o valor entregue depende de a auditoria estar configurada corretamente desde o primeiro dia — um evento que não foi coletado não existe pra sempre.

Antes de instalar: o que levantar

Tamanho e distribuição do ambiente

Quantos DCs, servidores, estações e NAS? Ambiente distribuído por WAN com 1000+ estações já indica que vai precisar de agente.

Conta de serviço

O cliente aceita Domain Admin pra acelerar a implantação, ou exige o setup de menor privilégio? Isso muda o cronograma — ver Permissões.

Retenção e requisitos de compliance

Qual mandato o cliente precisa atender (SOX, HIPAA, PCI DSS...)? Isso define o período de retenção de dados a configurar.

Edição a licenciar

Standard ou Professional — ver Licenciamento. Lembrando: o modelo é por servidor, não por usuário.

Integrações de resposta

O cliente já usa algum ITSM (ServiceNow, Jira, ServiceDesk Plus) para onde os alertas devem abrir chamado automaticamente?

File servers e NAS a proteger

Quais compartilhamentos são realmente sensíveis? Auditar tudo sem critério gera ruído — auditar pouco demais deixa buraco.

Instalação e primeiro acesso

Instale como serviço

Recomendado para produção — inicia com o sistema, roda com a conta de serviço configurada.

Configure o domínio

Informe a conta de serviço — Domain Admin para começar rápido, ou a conta de menor privilégio já preparada conforme Permissões.

Confirme os pré-requisitos do agente (se aplicável)

.NET Framework 4.5+ e 2GB de disco livre nas máquinas onde o agente será instalado.

Sequência recomendada de configuração

1. Políticas de auditoria

Deixe o ADAudit Plus configurar automaticamente a política de auditoria e o object-level auditing via GPO — é isso que a conta de serviço com os privilégios certos habilita.

2. Agentes, se necessário

Instale nos file servers/Windows servers que precisam de coleta em tempo real, e nas estações de redes distribuídas.

3. Perfis de alerta essenciais

Comece pelos alertas de maior sinal: lockout, conta desabilitada logando, membro adicionado a grupo privilegiado, log de auditoria limpo.

4. Relatórios de compliance agendados

Se o cliente tem mandato regulatório, agende a entrega periódica desde o início — não deixe pra configurar sob pressão de auditoria.

5. UBA e Attack Surface Analyzer

Habilite por último — o motor de UBA precisa de um período de baseline antes de ficar útil, então quanto antes ligar, antes ele fica preciso.

Checklist de validação pós-implantação

SMOKE TEST

✓ Eventos de pelo menos um DC aparecem em tempo real no console
✓ Se houver agente, o status dele aparece "conectado" no Admin
✓ Um alerta de teste (ex: lockout proposital) chega por e-mail
✓ Um relatório de compliance agendado é gerado e entregue corretamente
✓ A retenção de dados está configurada conforme o requisito do cliente
✓ A conta de serviço não tem mais privilégio do que o necessário (se foi esse o acordo)
