Conta de serviço e permissões

Provavelmente o setup de menor privilégio mais detalhado do ecossistema ManageEngine — e um dos pontos onde mais vale a pena caprichar numa implantação séria.

O atalho: Domain Admin

O ADAudit Plus começa a auditar imediatamente se você fornecer credenciais de Domain Admin na configuração do domínio. É o caminho mais rápido — mas em ambientes com política de menor privilégio, o produto também suporta rodar com uma conta configurada manualmente, sem Domain Admin.

MÚLTIPLOS DOMÍNIOS

Se você vai configurar mais de um domínio no ADAudit Plus, a recomendação oficial é criar uma conta de serviço separada por domínio, em vez de reutilizar a mesma em todos.

1. Criando o usuário, grupo e GPO de suporte

Crie o usuário de serviço

No AD, um novo usuário chamado ADAudit Plus — essa é a conta que vai receber todos os privilégios a seguir.

Crie o grupo de permissão

Um grupo ADAudit Plus Permission Group, com todos os DCs, servidores e estações que serão auditados como membros.

Crie a GPO de suporte

Uma GPO de nível de domínio chamada ADAudit Plus Permission GPO — é através dela que as permissões abaixo são distribuídas para todas as máquinas monitoradas de uma vez, em vez de configurar computador por computador.

Restrinja o security filtering

Remova a permissão "Apply group policy" do grupo Authenticated Users nessa GPO, e adicione o "ADAudit Plus Permission Group" no lugar — assim ela só se aplica às máquinas que você realmente quer auditar.

2. Privilégios para coleta de event log

Manage auditing and security log

Concedida via Computer Configuration → Policies → Windows Settings → Security Settings → Local Policies → User Rights Assignment na GPO de suporte — permite que a conta defina auditoria em nível de objeto.

Membro de Event Log Readers

Em Domain Controllers, direto no grupo builtin. Em servidores/estações, via preferência de grupo local distribuída pela mesma GPO.

AMBIENTES MUITO RESTRITOS

Em alguns casos, pertencer ao Event Log Readers não é suficiente para acessar canais específicos de log. Nesse caso, é preciso conceder acesso direto ao canal de segurança via linha de comando: wevtutil gl "security" para consultar a permissão atual, editar o valor de channelAccess adicionando a entrada (A;;0x1;;;S-1-5-32-573), e aplicar com wevtutil sl "security" /ca:<valor>.

3. Configuração automática de política de auditoria

Com esses privilégios, o ADAudit Plus consegue configurar sozinho a política de auditoria e o object-level auditing do ambiente — sem você precisar tocar em cada GPO manualmente:

Domain Controllers

Delegue permissão de "Edit settings" à conta de serviço diretamente na Default Domain Controllers Policy.

Servidores membro, estações e file servers

A conta precisa ser membro de Group Policy Creator Owners, além de permissões específicas de criar/excluir objetos de grupo e escrever membros de grupo no container Users.

4. Permissões específicas para auditoria de file server

Cobertas nos mesmos privilégios acima (Manage auditing and security log + Event Log Readers), mas vale reforçar: para tempo real, a máquina do file server precisa do agente cliente instalado — sem ele, a auditoria de arquivo ainda funciona, só não em tempo real.
