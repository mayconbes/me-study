Arquitetura

Como o PAM360 se posiciona entre o usuário e o recurso

A decisão de instalação mais impactante de um projeto de PAM: Windows ou Linux, e onde vai precisar de agente.

Windows vs. Linux: não é só preferência

O PAM360 roda nos dois sistemas com o mesmo conjunto de funcionalidades, mas a plataforma escolhida muda como algumas coisas funcionam na prática:

Instalação em Windows

Permite integração direta com Active Directory (importar usuários/grupos) e single sign-on via NTLM para quem já logou no domínio. Resets de senha em recursos Windows funcionam em modo agentless, desde que haja conectividade direta.

Instalação em Linux

A integração com AD depende de autenticação LDAP em vez de SSO nativo. Resets de senha em recursos Windows a partir de um servidor Linux exigem agente instalado no alvo.

NA PRÁTICA

Para clientes com ambiente majoritariamente Windows/AD e que querem SSO nativo, a instalação em Windows tende a exigir menos peças móveis. Ambientes já padronizados em Linux, ou com política de não rodar produto de segurança em Windows Server, vão para Linux e absorvem o agente onde for necessário.

Sessões sempre tuneladas pelo servidor

Toda sessão remota (RDP, SSH, VNC, SQL, Telnet) lançada pelo PAM360 é tunelada através do próprio servidor — não existe conexão direta entre o dispositivo do usuário e o host de destino. O usuário só precisa de um navegador compatível com HTML5; a credencial nunca trafega até o navegador, e nenhum plugin ou software adicional é necessário no endpoint do usuário.

Quando instalar o agente PAM360

Reset de senha em modo agentless

Funciona para a maioria dos recursos com conectividade direta a partir do servidor PAM360.

Quando o agente é necessário

Reset local em máquinas Linux a partir de servidor Windows, listeners de reset de senha, filtragem dinâmica de contas, elevação de privilégio self-service, e recursos de Zero Trust específicos do endpoint.

A instalação do agente é feita com uma Agent Key gerada no console — de uso único por padrão, ou configurável para ficar ativa por um número determinado de horas, permitindo múltiplas instalações no período. A chave nunca deve ser compartilhada, já que possibilita instalação não autorizada do agente.

Application Gateway: redes segmentadas

Para ambientes com redes remotas ou segmentadas (filiais, VLANs isoladas, ambientes de cliente em um MSP), o PAM360 Application Gateway atua como ponte segura entre o servidor central e essas redes — permitindo orquestrar acesso privilegiado de forma distribuída sem abrir conectividade direta ampla entre todos os segmentos.
